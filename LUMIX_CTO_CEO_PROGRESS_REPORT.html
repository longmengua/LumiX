交易架構現況

站內交易與外部流動性邊界
客戶命令 → 驗證／冪等／資產或保證金預留 → LumiX 客戶委託依價格、時間優先互撮 → 站內確定成交後寫入訂單、成交、持倉與不可變帳本 → 未成交量才可交 ExternalOrderProxy → 未來由 BINANCE 或其他 provider adapter 送出 → 只有外部確定成交才能確認客戶成交；逾時必須查原 clientOrderId

平台不採「先用自有庫存承接、再事後對沖」模式。外部尚未確定成交時，不得憑空建立可提領餘額或已完成持倉。

USDT 合約能力
  • BTCUSDT、ETHUSDT USDT 永續逐倉，允許同商品同時持有 LONG 與 SHORT。
  • LIMIT／MARKET、GTC／IOC／FOK、reduce-only、部分成交及安全撤單。
  • 已實現盈虧、funding 與保證金變更透過守恆 USDT 帳本處理。
  • 使用 Binance USDⓈ-M 公開 mark／index；資料過期即停止新增風險。
  • 強平只使用 LumiX 可成交委託；缺乏流動性或保險基金不足時停止增加風險，不假造平倉。
  • 非 USDT 抵押結算按需求延後，僅保留擴充邊界。
Proxy Demo 設計
  • Demo 是純後端能力，不新增測試 UI。
  • 只允許 loopback 與指定 Origin；結果只存在程序記憶體。
  • 同一 clientOrderId 與相同 intent 重送維持同一結果；不同 intent 拒絕。
  • DELAYED 初次回 PENDING，約三秒後查詢同一 clientOrderId 才回確定成交。
  • 資料庫開關預設 true，關閉後以不存在語意拒絕 Demo；設定更新有 optimistic version 與 audit log。
